01 — Overview

What is Vanvedha?

Vanvedha is not a multi-vendor marketplace — there is only one seller: Vanvedha itself. Vanvedha sources, processes, and owns the entire spice catalog, then sells it two ways at once: directly to individual Customers (retail), and in bulk to Retailers — shop owners who resell Vanvedha's spices in their own stores. Delivery Agents fulfill both kinds of orders, and Admin runs the whole operation.

🎯

Goal

Sell premium spices through two channels from one platform — single-pack retail sales to consumers, and bulk wholesale supply to retail shops — without running two separate systems.

🔄

How it works, in short

A customer buys one or two packs at retail price for home use. A retailer buys cartons/bulk quantities at a lower wholesale price to stock their shop. Vanvedha's own delivery network fulfills both — instantly for customers, on a scheduled bulk run for retailers.

05 — Behind the Scenes

Retailer, Delivery & Admin Workflows

Vanvedha is the only seller on this platform — there is no multi-vendor marketplace. Customers buy single packs at retail price; Retailers buy in bulk at wholesale price to stock their own shops. Delivery Agents fulfill both, and Admin runs the whole operation.

In short: Retailer = a buyer, not a seller on Vanvedha. They never list their own products on the platform — they only purchase from Vanvedha's catalog at the wholesale price set by Admin, in bulk, then sell it on through their own shop, outside the platform.

🛵 Delivery Agent — the fulfiller (for both channels)

A Delivery Agent is Vanvedha's own rider/driver. The same role handles both order types, just with a different rhythm.

👤

Customer Orders (Retail)

  • Single order, assigned as soon as it's placed
  • Picked up & delivered same-day, door to door
  • Status: Pending → Confirmed → Processing → Shipped → Delivered
🏬

Retailer Orders (Bulk)

  • Larger shipment, delivered on a scheduled run
  • Dropped at the retailer's shop, not a home address
  • Same status pipeline, sized for bulk quantity

Agents set their vehicle type, zone, and availability — Vanvedha still owns delivery end-to-end, it's never handed off to an outside courier.

🛠️ Admin — the operator

Admin is Vanvedha's own internal team, running the platform from a dedicated dashboard.

✅

Onboarding & Oversight

  • Approves or rejects new Retailer applications
  • Manages Delivery Agent accounts & zones
  • Oversees every user from one dashboard
💲

Pricing & Catalog

  • Sets retail price (for customers) and wholesale price (for retailers) per product
  • Manages product categories and tags
  • Creates discount coupons & moderates reviews
📌

Where things stand today

The codebase currently models a "Vendor" account — a shop owner who lists their own products and gets admin-approved. That's the right building block (registration, business details, admin approval are already there), but it needs to be repointed at the wholesaler/retailer concept above: rename Vendor → Retailer, remove their ability to list products, and instead give them access to a wholesale price list and a bulk-order flow.

Also still to be built: a second, wholesale price on every product (today each product/variant has only one price), a bulk order type separate from a normal cart order, and the scheduled/bulk delivery flow for Delivery Agents. Until then, the platform behaves as a single retail storefront only.

🔄 How permission resolution works

🏷️

Template (base)

The named permission preset — defines the default access for all staff assigned to it. Changing the template instantly updates permissions for all staff using it.

⚙️

Individual override (wins)

An override on a specific staff member always takes priority over the template. This lets Admin grant or restrict one action for one person without creating a whole new template.

07 — Behind the Scenes (Supply Chain)

Raw Material Procurement & Processing

Vanvedha doesn't just resell packaged spices — it buys whole/raw spices in bulk (raw chillies, raw turmeric, raw coriander, etc.) and processes them in-house (cleaning, drying, grinding) into the finished powders that Customers and Retailers actually buy. This is an internal operations module run by Admin/Ops — it has no customer, retailer, or delivery-agent facing side.

🔍

Full Lot Traceability

Every finished batch records exactly which raw material lot(s) it was ground from. If a quality issue ever comes up in a finished product, it can be traced straight back to the supplier and purchase it originated from.

🏷️

Barcodes

Both raw material lots and finished goods batches get a barcode — scan to pull up purchase/processing history, and to speed up stock counts, warehouse handling, and checkout/dispatch.

📌

Where things stand today

✅ Fully built and live. The entire procurement & processing module is implemented — backend models, REST API, database migrations, and Admin panel screens are all in place.

  • ✅ Supplier model + API + admin screen — add/edit/delete supplier records with name, phone, and address
  • ✅ Raw Material Lots model + API + admin screen — log every bulk purchase with spice type, quantity, price per kg, and purchase date; barcodes auto-generated as RAW-XXXXXXXXXX; stock-remaining progress bar per lot
  • ✅ Processing Batches model + API + admin screen — record which raw lots were consumed and what finished product came out; batches start as Pending and must be manually confirmed
  • ✅ Batch confirmation is atomic — confirming a batch deducts the used quantity from each raw lot and adds the pack count to the product variant's sellable stock, with row-level locking to prevent race conditions
  • ✅ Full traceability chain — every finished batch links back to its raw lots (ProcessingBatchRawUsage), so a quality issue can be traced to the exact supplier purchase
  • ✅ Barcode Lookup screen — scan or type any barcode (RAW-… or FIN-…) to instantly pull up the full record; auto-focuses between scans so the page works with a physical handheld scanner

The admin sidebar has a dedicated "Raw Material" section with four screens: Suppliers, Raw Material Lots, Processing Batches, and Barcode Lookup. Processing yield/wastage percentages are not tracked — just that raw stock went down and finished sellable stock went up.
